The DGCEO Document Hub Lifecycle

An end-to-end visualization of the automated document submission, tracking, and review process.

PHASE 1: SUBMISSION & AI TRIAGE

From initial upload to automated analysis

Document Upload

User visits the `home.html` portal and fills out the secure submission form (`index.html`).

Actor: Submitter

Secure API Call

`submit.js` converts the file to Base64 and sends the complete JSON payload to a secure Power Automate URL.

Actor: Portal (JS)

Flow Ingestion

Power Automate receives the data, saves the file to SharePoint, and logs a new item in the `DocumentTracker` list.

Actor: Power Automate

AI Auto-Analysis

The flow reads the PDF, sends its text to the Gemini API, and receives a JSON response with a summary, tags, and suggested routing.

Actor: AI (Gemini)

Instant Notifications

The flow sends a Triage Email (with AI analysis) to the internal team and a branded Confirmation Email (with Tracking ID) to the submitter.

Actor: Power Automate

Success & Receipt

The portal receives the "Success" response, generates a branded HTML receipt, and provides the user with a download link.

Actor: Portal (JS)

PHASE 2: SECURE TRACKING (2-FA)

Verifying identity to protect sensitive information

Lookup Request

User visits `track.html` and enters their Tracking ID and Email to request access.

Actor: Submitter

Code Generation

The Tracking Flow validates the ID/Email, generates a 6-digit random code, and saves it to SharePoint with a 10-minute expiry.

Actor: Power Automate

Code Sent

The flow sends the branded Verification Email (Template 7) to the submitter's email address.

Actor: Power Automate

User Verification

The user enters the 6-digit code into the portal. `track.js` sends a *new* request with the ID, Email, and Code.

Actor: Submitter

Access Granted

The flow validates the code and expiry time. If correct, it clears the code (for security) and sends the full status data back to the portal.

Actor: Power Automate

Status Displayed

`track.js` receives the data and renders the visual status stepper, showing the document's current position (e.g., "In Review").

Actor: Portal (JS)

PHASE 3: REVIEW & CLOSURE

Internal management and automated updates

Internal Triage

Your team reviews the new item in the Power App Dashboard, using the AI Summary and Tags to make a decision.

Actor: Internal Team

Status Change: "In Review"

The team updates the item's Status field in the Power App from "Submitted" to "Under Review (EA)" and saves.

Actor: Internal Team

Automated Notification

A *separate* "On Modified" flow triggers instantly, sees the status change, and sends the "In Review" email (Template 3) to the submitter.

Actor: Power Automate

Internal Action

The document is forwarded to the relevant department (e.g., Legal) for action, or handled by the DG's Office directly.

Actor: Internal Team

Status Change: "Closed"

Once all actions are complete, the team updates the Status in the Power App to "Closed," archiving the item.

Actor: Internal Team

Process Complete

The "On Modified" flow triggers again, sending the final "Closed" email (Template 5) to the submitter, completing the lifecycle.

Actor: Power Automate
